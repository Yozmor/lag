<h1 align="center">Лаг (Lag)</h1>

Консольная утилита для Windows, которая проверяет состояние интернет-соединения и сохраняет подробный отчёт. Помогает понять, где проблема: сайт заблокирован или лежит, подменяет ли DNS ответы, работает ли VPN, на каком узле маршрута теряются пакеты.

Назван в честь лага — морского прибора, которым измеряли скорость судна. Один `.exe` без внешних зависимостей.

## Возможности

**Доступность сайтов**
- Проверка списка сайтов по HTTP напрямую и через VPN.
- Сама определяет режим VPN: прокси (системный прокси Windows) или туннель (TUN). Показывает внешний IP и страну, чтобы было видно, через что реально идёт трафик.
- Сайты, которые открываются только через VPN, подсвечиваются отдельно.

**Полная диагностика (HTTP + DNS)**
- Для каждого сайта отправляет DNS-запросы сразу к нескольким DNS-серверам и сравнивает ответы.
- Если разные DNS отдают разные IP, это подсвечивается: частый признак подмены DNS провайдером.
- Можно проверить любой свой хост, не только из списка.

**Трассировка**
- TCP-трассировка до узлов из списка или до любого своего хоста через [NextTrace](https://github.com/sjlleo/nexttrace), с геолокацией узлов маршрута.
- NextTrace скачивается автоматически при первом использовании.

**Сканирование портов**
- Проверка популярных портов (SSH, HTTP/HTTPS, FTP, SMB, базы данных и т. д.) на хостах из списка или на своём хосте.
- Читает баннеры сервисов, определяет версию и ОС.
- Сверяет версии OpenSSH, Apache, nginx, MySQL, PostgreSQL, vsftpd, ProFTPD со встроенной базой известных уязвимостей (CVE).

**Прочее**
- Каждый запуск сохраняет отчёт в текстовый лог, логи раскладываются по папкам по типу подключения (Wi-Fi с именем сети, Ethernet и т. д.).
- Старые логи удаляются автоматически (по умолчанию старше 180 дней).
- Проверка обновлений с GitHub и обновление в один клик.

> ⚠️ Сканируй только свои устройства и сети, на которые у тебя есть разрешение. Сканирование чужих серверов без согласия владельца может нарушать закон.

> Проверка уязвимостей — эвристика по номеру версии из баннера. Дистрибутивы часто закрывают уязвимости, не меняя номер версии, поэтому возможны ложные срабатывания.

## Установка

1. Скачай [`Lag.exe`](Lag.exe): кликни по файлу, затем кнопка **Download raw file** (стрелка вниз справа).
2. Положи его в отдельную папку, например `C:\Tools\Lag`. Рядом программа сама создаст папки `Settings` (списки и настройки), `Logs` (отчёты) и `Tools` (туда при первой трассировке скачается NextTrace).
3. Дважды кликни `Lag.exe`. Windows попросит права администратора: они нужны для трассировки. Откроется меню.

Нужна Windows 10 или 11. Больше ничего ставить не надо.

```
========== МЕНЮ ==========
1 - Проверить доступность сайтов
2 - Трассировка
3 - Сканирование портов
4 - Настройки
0 - Выход
```

При первом запуске в папке `Settings` появятся пустые списки, заполни их (см. ниже) и запусти проверку снова.

## Настройка списков

При первом запуске рядом с программой появится папка `Settings` с файлами-списками. Заполни нужные:

| Файл | Для чего |
|---|---|
| `sites.txt` | Сайты для проверки доступности и DNS |
| `dns_targets.txt` | DNS-серверы для сравнения ответов |
| `trace_targets.txt` | Цели для трассировки |
| `scan_targets.txt` | Хосты для сканирования портов |
| `ports.txt` | Порты для сканирования: порт или диапазон `8000-8010` (создаётся с 27 популярными портами) |
| `config.json` | Таймауты и прочие настройки |

Формат списков — одна строка на цель, после `;` можно написать комментарий. Строки, начинающиеся с `#`, пропускаются:

```
# Список целей
# Формат: значение;комментарий
youtube.com;YouTube
1.1.1.1;Cloudflare DNS
```

### Настройки (`config.json` или меню «4 - Настройки»)

| Параметр | По умолчанию | Что это |
|---|---|---|
| `ConnectionTimeout` | 1500 мс | Таймаут подключения к порту при сканировании |
| `BannerTimeout` | 2000 мс | Сколько ждать баннер сервиса |
| `HttpTimeout` | 5 сек | Таймаут HTTP-запроса при проверке сайтов |
| `MaxLogAgeDays` | 180 дней | Срок хранения логов |
| `MaxHops` | 30 | Максимум узлов при трассировке |

## Куда сохраняются отчёты

```
Logs\<тип подключения>\<раздел>\<дата_время>.txt
```

Путь к файлу показывается в конце каждой проверки.

## Обновление

Меню **4 - Настройки → 7 - Проверить обновления**. Программа сравнит свою версию с версией на GitHub и, если есть новая, скачает и установит её. Твои списки, `config.json` и логи при обновлении не трогаются.

Если у тебя стоит старая версия под именем `NetworkReport.exe`, она обновиться сама не сможет (репозиторий переименован). Просто скачай новый `Lag.exe` в ту же папку: списки в `Settings` и логи подхватятся, а `NetworkReport.exe` можно удалить. То же самое для версий под именем `Lagg.exe`: скачай `Lag.exe`, старый `Lagg.exe` удали.

## Сборка из исходника

Нужен Visual Studio (компонент «Разработка классических приложений на C++») или MinGW-w64 (`g++` в PATH). Скачай репозиторий (**Code → Download ZIP**) и запусти `build.bat`: он сам найдёт компилятор и соберёт `Lag.exe` с иконкой.
