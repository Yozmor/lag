<h1 align="center">Лаг — Windows</h1>

Оконная версия (Direct2D). Один `.exe` без внешних зависимостей, Windows 10/11.

## Установка

**Готовый бинарник.** Скачай [`Lag.exe`](Lag.exe) (кнопка **Download raw file**), положи в отдельную папку, например `C:\Tools\Lag`, запусти. Рядом появятся `Settings`, `Logs`, `Tools`. Для трассировки Windows попросит права администратора.

**Сборка из исходника.** Нужен Visual Studio (компонент «Разработка классических приложений на C++») или MinGW-w64 (`g++` в PATH). Запусти `build.bat` — он сам найдёт компилятор и соберёт `Lag.exe` с иконкой.

Нужна Windows 10 или 11.

## Интерфейс

Окно с меню слева и панелью справа. Навигация — мышью или с клавиатуры:

- **Tab** — переключить фокус между меню и окном.
- **↑↓** — выбрать пункт / листать; **←→** — значения и таблицы.
- **Enter** — запустить проверку / открыть; **1–6** — быстрый запуск раздела.
- Колесо/`+`/`−` — зум интерфейса.

Разделы: **Сайты**, **DNS**, **ЗОНД**, **Трассировка**, **Порты**, **Сеть / VPN**, **Настройки**, **Отчёты**, **Списки**.

Проверки нельзя запускать одновременно — пока идёт одна, вторая не стартует (параллельные пробы мешают друг другу, особенно контролю ЗОНДа).

## Списки (раздел «Списки» или папка `Settings`)

| Файл | Для чего |
|---|---|
| `sites.txt` | Сайты для проверки доступности, DNS и ЗОНДа |
| `dns_targets.txt` | DNS-серверы для сравнения ответов |
| `trace_targets.txt` | Цели трассировки |
| `scan_targets.txt` | Хосты для сканирования портов |
| `ports.txt` | Порты: число или диапазон `8000-8010` |
| `stun_targets.txt` | Свои STUN-серверы для точной карты UDP (необязательно) |
| `config.json` | Таймауты и настройки |

Формат списков: одна цель в строке, после `;` — комментарий, строки с `#` пропускаются.

### Настройки (`config.json` или раздел «Настройки»)

| Параметр | По умолчанию | Что это |
|---|---|---|
| `ConnectionTimeout` | 1500 мс | Таймаут TCP-connect при сканировании |
| `BannerTimeout` | 2000 мс | Сколько ждать баннер сервиса |
| `HttpTimeout` | 5 сек | Таймаут HTTP-запросов и TLS-проб |
| `MaxLogAgeDays` | 180 дней | Срок хранения логов |
| `MaxHops` | 30 | Максимум узлов при трассировке |
| `SocksPort` | 0 (авто) | SOCKS-порт прокси-клиента; 0 = HTTP-порт − 1 |

## Отчёты

```
Logs\<тип подключения>\<раздел>\<дата_время>.txt
```

Рядом с отчётами ЗОНДа и «Сети/VPN» пишется `.json` — машиночитаемый снимок (вход для будущего адаптивного клиента). Путь к файлу показывается в конце каждой проверки. Старые логи чистятся автоматически.

## Обновление

Раздел **Обновление** (или «Настройки → Проверить обновления»). Программа сравнивает свою версию с `windows/Lag.cpp` в репозитории и, если новее, скачивает архив и копирует исходники. Твои списки, `config.json` и логи не трогаются.

> Обновление подтягивает **исходники**. Если в репозитории нет собранного `Lag.exe`, после обновления перезапусти `build.bat`, чтобы пересобрать. Готовый `Lag.exe` в репозитории обновляется и запускается автоматически.

Старые имена (`NetworkReport.exe`, `Lagg.exe`) сами обновиться не могут — просто скачай новый `Lag.exe` в ту же папку, списки и логи подхватятся, старый файл удали.

## Файлы

| Файл | Что это |
|---|---|
| `Lag.cpp` | Ядро: проверки, отчёты, обновление, состояние сети |
| `LagProbe.cpp` | ЗОНД: TLS-проба, DoH, тест обхода, UDP/STUN, NAT |
| `LagUI.cpp` | Окно (Direct2D), подключает `Lag.cpp` и `LagProbe.cpp` |
| `build.bat` | Сборка (MSVC или MinGW) |
| `app.rc`, `Icon/icon.ico` | Иконка |
